# ADR 0023 — Jev-coordinated application preparation and human action boundary

- Status: Accepted — M0–M5 implementation and synthetic gates recorded; one real-data pilot and optional follow-ons remain gated/deferred
- Date: 2026-10-06
- Related: [PLAN-019](../plans/PLAN-019-application-preparation-framework.md), [ADR 0006](0006-jev-scoring-and-budget-guard.md), [ADR 0016](0016-durable-applied-tracker.md)

## Context

Clue discovers and ranks jobs with the existing Jev integration. The product keeps application decisions and submission on the employer's site, and its applied tracker distinguishes owner attestation from receipt evidence. The local preparation framework pairs Jev with a bounded OpenAI API agent. PLAN-020 records synthetic runs, including a visually inspected packet; a later synthetic listing returned Jev `review` and correctly stopped before GPT. Review of a generated packet and one manually triggered real-data pilot remain open.

Jev is the matching validator. GPT-6 Luna (`gpt-6-luna`, `reasoning.effort=high`) directs bounded public research and prepares tailored CVs, cover letters, application answers, and outreach drafts. It uses the existing Scrapling-backed Clue crawler, permitted technical profiles bound to the selected listing, stage-scoped descriptive-profile context, and owner-selected CVs for content/layout. After the manual trigger, Recruiter and Rewriter receive each permitted technical profile in full plus exact source-bound evidence IDs; unreviewed suggestions can be used without one-by-one pre-approval, but each generated factual block must pass Jev support against its cited excerpt and the complete packet remains subject to owner review. The optional Hiring Manager practice stage can use the technical profile after its own owner action. The Researcher gets no private profile; the Diagnoser sees the selected CV and job context. Only the Rewriter gets selected descriptive context and writing references. Owner-written descriptive material may support a directly stated preference. Material with unknown or AI-assisted authorship is an optional style guide only and cannot support first-person motivation or factual claims. The owner can set a default CV or let the agent recommend/select from permitted references and can choose whether to preserve or improve their structure. Before each generation, Clue counts the complete request, checks it against the current model context window, and reserves app-side spend from the exact input-token count and stage output allowance. Clue does not truncate selected source material by character length. Clue's ordinary code owns hard gates, state, source/claim validation, budgets, permissions, and local rendering. The owner reviews the complete packet at one final checkpoint, manually submits applications, and manually sends outreach. [ADR 0024](0024-model-aware-token-budgeting.md) supersedes this ADR's former profile character limits.

## Decision

1. Preserve the existing Jev model, rubric, match/filter/qualification/seniority outputs, and current budget behavior. Jev remains the sole authority for candidate/job matching.
2. Run applicable deterministic hard gates and Jev assessment before generation. Pass the persisted Jev result to the GPT agent as read-only, versioned context. A Jev conflict blocks draft generation; review or unassessed results require owner resolution. GPT may flag a possible mismatch but cannot calculate, rank, write, or override Jev decisions. Re-run Jev only when its inputs or rubric materially change.
3. Use the [OpenAI Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) with model ID `gpt-6-luna` and the configured `reasoning.effort: "high"`. Set `store:false`; this avoids Responses application-state retrieval but does not guarantee zero retention. Clue presents the data-handling disclosure before the user-triggered data flow, and the user must review it before selecting personal inputs. Account-specific retention eligibility is outside Clue's verification. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) define artifact schemas. Function calls are proposals; the local harness executes only explicitly allowlisted tools after checking arguments, scope, URLs, consent, and budget.
4. Put all external research in a distinct Researcher stage using the existing Scrapling-backed Clue crawler. The Researcher receives job/company search context but no CV, profile, or private claim data, and returns sourced facts, excerpts, timestamps, uncertainty, and contact evidence where enabled. The later writing/practice stages receive that cited packet and have no crawl or general network tools. Do not give any model stage arbitrary filesystem, database, shell, or logged-in browser access.
5. Send only the selected CV, read-only Jev result, permitted technical profiles, and selected writing context needed by the current owner-triggered listing. Bind the technical-profile source IDs, content hashes, and unreviewed evidence references to that trigger; pass each selected technical profile to Recruiter and Rewriter in full. The optional Hiring Manager receives this context only after a separate practice action. The Researcher receives no private profile; the Diagnoser receives the selected CV and job context. Only the Rewriter receives selected descriptive profiles or writing samples, in full. An owner-written descriptive profile may support a directly stated preference. Unknown or AI-assisted authorship permits style use only and never supports a factual or first-person claim. Recruiter/Rewriter may cite unreviewed technical-profile evidence IDs, but Jev must assess each generated content block against its exact linked excerpt; Jev's support judgment does not independently verify the underlying source, and owner review remains mandatory. Before each generation request, count its exact input and reserve local spend from the returned input-token count and configured output allowance; reject over-context requests before generation without truncating profile text. The selected CV/profile content is personal data; require separate OpenAI opt-in. Keep other CVs and unselected writing samples local. Preserve originals; local rendering creates versioned copies and applies the selected structure unless the owner opts into improvements.
6. Do not expose Gmail, message-send, connection-request, employer-form, or application-submit tools to GPT. After the owner reviews and approves the exact outreach recipient, subject, and body, a separate UI-triggered Gmail adapter may create an unsent draft; the owner sends it manually. Clue needs its own Google OAuth or connector authorization; the Gmail connector available in Codex does not transfer to the API agent. Gmail's `gmail.compose` scope supports draft management and sending, so the adapter must isolate the credential and expose draft creation only. If the owner requires a credential without send capability, use a Clue-local or `.eml`/copy-to-Gmail handoff instead.
7. Keep local rendering deterministic and versioned. The agent cannot overwrite source CVs. Reject stale inputs and any claim/profile evidence ID not bound to the trigger; show the owner the complete final output, source excerpts, unresolved questions, and changes. Schema compliance does not establish semantic truth. Before rendering, run a separate Jev support check on each generated resume edit, cover-letter paragraph, answer, and outreach draft against only its linked approved claims, exact technical-profile excerpts, or verified public excerpts. Only a directly stated preference in an owner-authored descriptive profile may support a cover-letter preference statement, and the exact source ID and close excerpt must be linked. Unknown or AI-assisted descriptive profiles are never evidence for first-person motivation or factual claims. Descriptive sources are never career evidence and cannot support work history, skills, qualifications, responsibilities, outcomes, or achievements; Clue must not link a loose topic overlap as evidence. Jev returns `supported`, `contradicted`, or `unresolved`; only supported blocks enter generated files, while unresolved/contradicted items remain visible in the local evidence report. A deterministic numeric/date guard can downgrade unsupported values even when Jev says supported. This check must not read or mutate Jev's saved match, filter, qualification, or seniority result.
8. Keep Jev and OpenAI usage in separate local ledgers with independent request controls. Clue may reserve and settle its own requests only; it does not modify provider-account caps or other account settings. Keep rate-card revisions current and usage reservations recoverable. The evaluation runner retains unsettled reservations and blocks untracked retries. Never silently lower reasoning effort or switch providers when blocked.
9. Treat provider and tool prices as volatile. Refresh the configured rate card before a live request and record its revision with local usage estimates. These estimates are not a provider invoice or an account-wide cap.
10. Keep application forms and submissions manual and outside Clue. A packet never marks an opportunity as applied; the existing applied tracker remains authoritative. Clue may record a later owner attestation or receipt. Do not provide a send or submit function.
11. Keep claims, CVs, opportunities, packets, contact research, consent, and usage records local. Do not commit personal source documents, claim values, contacts, answers, or generated packets to the public repository.
12. Orchestrate distinct GPT-6 Luna (`reasoning.effort=high`) stages with strict schemas: Diagnoser audits locally extracted resume text/layout for observable readability risks; Recruiter maps job criteria to approved claims and bound technical-profile evidence IDs and reports CV document coverage while displaying Jev read-only; Rewriter proposes evidence-bound bullet patches using Google's X/Y/Z accomplishment pattern; Hiring Manager optionally runs role-specific interview practice and scores only the owner's answers against a transparent practice rubric. The Recruiter must not create a competing candidate-fit score. The Diagnoser must not claim to simulate an unknown employer ATS or explain ghosting. The Rewriter must not invent or estimate metrics, and metrics are not required in every bullet. The Hiring Manager's ratings are not Jev results, hiring predictions, or employer scores. These roles use the same configured GPT-6 Luna model as separate orchestrated calls; they do not hold independent credentials or tools. Jev remains the only matching validator and may inform practice topics from its read-only gaps, but it does not score ATS parseability, prose, bullets, or interview answers.
13. Keep preparation opt-in per listing. Normal discovery, identity deduplication, deterministic hard gates, Jev matching, and ranking may run automatically as they do in the search workflow, but they must never start Researcher or GPT writing/practice calls. Only the owner clicking **Prepare application** on a specific eligible `match` listing creates a preparation request for that opportunity. No bulk-selection, recurring job, or background queue may create triggers. Bind the click to the job snapshot, Jev run, and relevant profile/CV/claim/policy revisions; reserve OpenAI budget only after the click; make repeated clicks idempotent. The click runs the complete research and document packet for that listing. Mock interview practice is a separate optional owner-triggered action. Final review, Gmail draft creation, and manual send/application submission retain their existing boundaries.
14. Treat a permitted technical profile as owner-supplied source material, not independent verification. It can be used after the listing trigger without pre-approving each extracted suggestion, but candidate statements must cite a bound evidence ID and Jev must check the generated block against its exact excerpt. Source IDs, hashes, and unreviewed evidence references are part of the immutable request binding; source or evidence changes make the request stale. The final owner packet review remains required. Keep this use scoped to Recruiter/Rewriter and separately triggered Hiring Manager practice; the Researcher never sees private profiles, and the Diagnoser receives only the selected CV plus job/Jev context.

## Consequences

- Core M0–M5 local workflow code is implemented. The app adds evidence review, a per-listing preparation queue, bounded research/generation, versioned artifacts, exact packet approval, owner-reported outcomes, and an isolated Gmail draft adapter.
- Jev continues to own matching; the GPT agent is a bounded research and content worker. Its results cannot change match eligibility.
- OpenAI use is gated by Clue's separate consent, local usage controls, a current rate card, and a non-empty local key. `.env.example` remains blank. The disclosure distinguishes Clue's local request controls from provider-account settings. Synthetic generation passed Jev support, local usage settlement, DOCX content checks, and visual inspection; review of a generated packet remains open. No real candidate profile was used.
- A local usage reservation and settlement ledger must account for input/output usage and applicable tool charges. Timeouts with uncertain usage retain the reservation until reconciled.
- New private records use additive SQLite schema creation and are included in search-reset retention and full personal-data deletion. Synthetic tests cover the new data cleanup paths.
- Candidate evidence is reviewed during initial local source onboarding; after that setup, each opportunity has one final packet review. The owner may then ask the separate adapter to create an unsent Gmail draft, but must send it themselves; application forms and submissions stay manual.
- Search and Jev matching may operate automatically; GPT research and preparation begin only from a deliberate per-listing owner action. Unrequested listings consume no OpenAI or contact-crawl budget.
- Gmail draft creation requires a scope that also permits sending. The model has no Gmail tool, and the adapter must omit send operations. A local email handoff is the fallback when that credential scope is not acceptable.
- GPT-6 Luna uses the configured `high` effort. The local ledger records stage-level tokens, tool use, and estimated/settled cost. The latest 12-project synthetic run passed Jev support for four factual blocks, final tailored-resume approval, packet checks, and DOCX visual inspection. An earlier synthetic Recruiter output exceeded its allowance; token-aware admission and the adjusted stage budget now have regression coverage. Review of the exact generated packet remains open.
- Owner-set in-app reminders and packet effort/usefulness feedback are part of the local manual-trigger workflow. Relevant owner-recorded replies, interview/status changes, and inactive listings cancel active reminders. Clue does not send proactive notifications, read mail, or send follow-up messages. The outcome view separates pending applications from explicitly resolved statuses and ties packet feedback to the exact approved version. The optional background worker, external tracker synchronization, calibrated cohort analytics, and proactive notifications remain deferred until there is measured usage or an explicit owner decision.
