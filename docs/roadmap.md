Use Scrapling as the replaceable crawl adapter with `robots.txt` `Disallow` ignored, eight global requests, two per domain, a one-second base delay, bounded public-page traversal, and dynamic rendering for discovered public career shells. **Acceptance:** Listing provenance, last-check age, delisting/expiry, duplicates, source-link validity, parse success, blocks, and compute cost are measured. All non-TypeSafe costs remain $0.

**Acceptance:** A written evaluation supports score labels and confidence display; hard constraints behave deterministically; all displayed jobs have source evidence; low-confidence/unvalidated-language results stay unscored; all non-TypeSafe recurring costs stay $0.

## 8. Jev-coordinated application preparation

[PLAN-019](plans/PLAN-019-application-preparation-framework.md), [PLAN-021](plans/PLAN-021-evidence-led-generation-quality.md), and accepted [ADR 0023](decisions/0023-application-preparation-and-action-boundaries.md), [ADR 0024](decisions/0024-model-aware-token-budgeting.md), [ADR 0025](decisions/0025-jev-approval-of-tailored-resume.md), [ADR 0026](decisions/0026-jev-categorical-evidence-support.md), and [ADR 0027](decisions/0027-explainable-jev-resume-review.md) record the implemented local flow and remaining enablement work. Jev remains the sole matching validator. After a single-listing **Prepare application** click, the local Clue harness passes its read-only, versioned result to GPT-6 Luna (`gpt-6-luna`, `reasoning.effort=high`) through the OpenAI Responses API. A separate Researcher directs bounded public contact research through the existing Scrapling crawler; the Diagnoser, Recruiter, and Rewriter generate evidence-grounded CV, cover-letter, answer, and outreach drafts. The Researcher receives no candidate profile; Diagnoser receives the selected CV plus job/Jev context; Recruiter/Rewriter receive each permitted technical profile in full, together with exact evidence references; only Rewriter receives selected descriptive profiles and writing references in full. Before generation, Clue counts each stage request with OpenAI's token-count endpoint, checks the current model context window, and reserves local spend from the exact input count and configured output allowance. Optional Hiring Manager practice gets technical-profile context after its own action. Jev checks each generated factual block against the exact cited excerpt, then separately must explicitly approve the final tailored resume against the saved job. That final decision cannot mutate the original match, and its uncalibrated confidence is diagnostic only. A reviewable packet also requires at least two Jev-supported, role-sourced cover-letter body paragraphs; failures produce no documents. Unknown or AI-assisted descriptive profiles are style guidance only. The owner may select a base CV and preserve or improve its structure. Clue validates and renders versioned drafts locally; the owner reviews the complete packet once before any external action.

The implemented flow includes reviewed evidence, a durable queue, Jev-to-GPT snapshot handoff, structured stage outputs/tool allowlists, local rendering, separate API usage accounting and consent, bounded public contact research, suppression, owner feedback, and an exact-approval Gmail draft adapter. Jev checks generated blocks against approved claims, exact technical-profile excerpts, and verified public evidence. Descriptive-profile evidence can support preferences only when its source is owner-authored; unknown/AI-assisted descriptive profiles are style guidance only. Technical-profile excerpt support is not independent verification. The repository API key remains empty; Clue usage controls and data-sharing consent are application-level gates, separate from provider-account caps. The latest 12-project synthetic `SYN-02` packet passed generation, Jev support and final-resume approval, usage settlement, DOCX reopen, and visual inspection. A repeated `SYN-01` stopped before GPT after Jev returned `review`; an earlier full synthetic run passed. The final bounded live packet also passed 2/2 cover-letter paragraph support, explicit final-CV approval, packet quality, and visual inspection. Its original listing state remained `review`; the CV had zero bullet edits, no contact was verified, and no outreach or application action occurred. Exact-packet owner review, broader portfolio and personal-voice acceptance, and personal-fit calibration remain open. See PLAN-020 and ADR 0030. Applications and sent outreach remain manual; the GPT agent has no Gmail or send tool. Automated reminders, external tracker sync, cohort analytics, and an optional worker remain deferred.

Search discovery, deduplication, deterministic hard filters, and Jev matching remain automatic. Mined or selected listings do not start research or generation. A scored listing with verified location eligibility waits for the owner to click its specific **Prepare application** card action when Jev says `match`, or **Prepare for review** when Jev says `review`; the dossier preserves that state and shows unresolved checks. Conflict, unassessed, and unverified/ineligible location results remain blocked. The individual click triggers the full bounded research and document packet for that job and reserves its OpenAI budget. No bulk or scheduled start is allowed. Mock interview practice is a separate optional trigger for that listing. M2's generated flow uses a separate GPT-6 Luna Researcher role (the only stage with bounded public-crawl tools), followed by Diagnoser, Recruiter, Rewriter, and optional Hiring Manager practice calls at `reasoning.effort=high`. The Diagnoser reports visible extraction/layout risks, not exact ATS outcomes; the Recruiter maps job criteria to evidence while Jev remains the only fit validator; the Rewriter applies the Google XYZ pattern only to verified facts and metrics; interview ratings remain practice feedback. A separate Jev support check assesses each generated block only against linked approved evidence, verified public sources, saved job facts, or a narrowly scoped owner preference source for a cover-letter preference; unsupported and unresolved blocks are omitted before rendering, and this check cannot alter matching. See PLAN-019 and ADR 0023/0028 for workflow contracts and PLAN-020 for evaluation status.
